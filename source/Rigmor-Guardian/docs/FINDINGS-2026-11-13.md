# Rigmor series survey, 2026-11-13

Mods: `Rigmor of Bruma` (Rigmor.esp, v1.1c), `Rigmor of Cyrodiil` (RigmorCyrodiil.esm + Patch.esp, v1.0), `Rigmor of Cyrodiil Texture Upscale` (3 BSAs + 3 loader ESPs), `Rigmor Rose Watcher` (Papyrus), `Rigmor Guardian` (new native DLL, this repo).

## Scripts
- Bruma 932 .pex/.psc in Rigmor.bsa (630 dialogue-line, 188 scene, 58 quest fragments, ~55 custom); Cyrodiil 1,736.
- `Utility.Wait`: 415 calls (Bruma) + 1,003 (Cyrodiil); 140 waits >= 5 s. Worst: QF_RigmorDLCQuest05 (74), ROCQuest05 (68), ROCQuest06 (67), DLCRSaints (60), ROCQuest09 (53), ROCQuest07 (52), Bruma qf__0204a704 (48).
- Almost no polling: RegisterForSingleUpdate in 1 (Bruma) / 4 (Cyrodiil) files. SetStage 848 + 1,519 lines, Scene Start 353 + 715, EvaluatePackage 194 + 62, MoveTo 164 + 479.
- No other mod ships a loose .pex with a Rigmor script name (checked every mod folder): no script-override conflicts.
- Log warning `defaultsetstageonplayeracquire ... NettleBalm` is a stale extra property on a vanilla script: harmless. (An earlier note predicting a stage-145 stall from it was an inference and is not supported.)
- Log error `Rigmor_SlaversListScript ... base types do not match` (ref 281B71:Rigmor.esp, quest fragment 0202c03f): the ledger pickup script cannot bind. Minor; unresolved, needs a look in xEdit.

## Texture archives (all BSA v105 = SSE format, nothing is LE-format)
| archive | dds | formats | notes |
|---|---|---|---|
| Rigmor - Textures.bsa (Bruma) | 523 | 201 uncompressed (115 MB), DXT5 143, DXT1 106, DXT3 73 | 22 without mipmaps |
| RigmorCyrodiil - Textures.bsa | 8,251 | DXT1 6,551 (942 MB), DXT5 646, DXT3 345 (503 MB), BC7 690, 17 uncompressed | 125 without mipmaps; 338 terrain LOD tiles unreadable by my scanner (not verified) |
| Upscale 01/02/03 | 1,442 | BC7 (all, mipmapped), 2K mostly, 6 at 4K | 5.9 GB; overrides 1,441 base files (962 larger, 241 same size, 3 smaller) |
- Upscale content: 586 normal maps (2.4 GB), 755 diffuse (3.1 GB), 62 `_m`, 20 `_d`, 8 `_msn`, 5 `_g`, 4 `_s`, 2 `_em`.
- Defects: `rigmorseaofghosts/breti/02.dds` and `silver.dds` have corrupt DDS headers; `armor/rigmor/rings/goldbear_d.dds` (upscale) is 1022x1024 uncompressed; tree LOD / object LOD atlases (4096 DXT3, plus a duplicate under `objects/new folder (3)`) are Rigmor's own pre-baked LOD and are made stale by AnvilLOD/DynDOLOD output.
- Not-overridden base textures: 7,045 files, 989 MB, 38 DXT3 files (171 MB). DXT3 -> BC7 does not save space (same bits per pixel), it only changes quality.
- Conclusion: SE/AE changed nothing about DDS. BC7 + mipmaps is correct. What is left is VRAM/disk policy (6 GB of 2K BC7 for one quest mod) and the handful of defects above.

## Meshes
- Rigmor.bsa: 348 nifs, 152 are Skyrim-LE stream-83 NiTriShape (armor 61, clothes 18, actors 17, clutter 15, dungeons 11, weapons 6, terrain/tamriel 19, ...), 196 are SSE (stream 100).
- RigmorCyrodiil.bsa: 1,950 nifs, 66 LE (all `terrain/rigmor_cyrodiil/houses`), 1,884 SSE.
- SSE loads LE nifs, so this is not a crash cause; it is a conversion/optimization candidate (not done).

## Native watcher (E:/WorkSpace/Rigmor-Guardian)
- CommonLib has no definition of TESSceneEvent, so scene start/stop cannot be sunk safely; the DLL reads BGSScene::isPlaying / currentPhaseIndex once a second instead, and uses TESQuest::currentStage.
- Actions go through the same Papyrus natives the mod uses (Scene.Stop, Quest.SetStage, Actor.EvaluatePackage).
- Ships in OBSERVE mode (`settings.act=false`): logs RULE/STALL lines to RigmorGuardian.log and does nothing else. Built clean, UNTESTED in game.
